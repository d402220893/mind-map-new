# 覆盖文件防护方案（设计稿 v4，目标 v2.0.60+）

> 范围：本文件是**设计/方案**，不落地代码。所有改动点在对应章节给出"落点 + 验收"，便于后续分批实现并各带回归测试。  
> 配套代码锚点均为当前仓库真实位置（基于 v2.0.59 代码）。  
> **v4 修订（2026-10-14，第三轮评审）**：针对 v3 的 3 个真硬伤 + 4 个待定边界 + 1 个战略拆分建议全部吸收——最关键的是 **P0 必须自带 `failed` 终态**（v3 把 loading/failed 推迟到 P1，导致坏文件/空文件无归宿、新建空簿到不了 loaded），以及 **P0 拆成 P0a（状态机止血，纯前端）+ P0b（写安全，动主进程）两包**，恢复"最小改动先上"初衷。详见 §0.2。

---

## 0. 一句话结论

"覆盖文件"不是单点 bug，而是**「有路径 ≠ 有可信数据 ≠ 能保存」三者被混为一谈**。  
根因链：`manualSave`（捕获内存数据）→ `silentSaveToFile`（覆盖写盘）**全程不校验"当前数据是否可信"**，且加载态靠 `Edit.vue:829` 的 **1.5s 兜底定时器**兜底——定时器一提前触发，`_isLoading` 被错误清零，于是**半加载/空数据也能走到保存**，覆盖掉原文件。

两层目标：

- **止血（P0a + P0b + P0.5，各自可独立出包）**：删除 1.5s 定时器并让 `loaded`/`failed` **只由真实完成事件/真实错误触发**；未加载完禁止写；打开即 seed 基准；覆盖前先备份（原子写 + 解析回读）；退出异步化；启动感知异常退出。
- **修根本（P1）**：补全 `loading` 态 + stall 探测器 + 把同步重活移出 UI 线程。

## 1. 设计层面两条铁律

1. **区分"文件路径" / "可信数据" / "可保存"**：`filePath` / `trustedData`（状态机确认 `loaded` 或可信空 `loaded`）/ `saveable=(loadPhase==='loaded')&&dirty` 三者解耦。
2. **任何覆盖写操作都可回滚**：写前备份；`tmp+rename` 原子替换；写后解析回读校验。绝不允许裸覆盖。

### 1.1 workbookState 字段设计（每 workbook 对象）

- `loadPhase: 'idle'|'loading'|'loaded'|'failed'`。
  - **P0a 落地 `idle`/`loaded`/`failed`**（`failed` 终态不可推迟到 P1，否则坏文件/空文件无归宿）。
  - P1 补 `loading`（decode+构建+首帧期间）。
- `lastGoodSize: number|null` —— 最近一次通过校验的成功写字节数；**打开即 seed 为文件真实大小**（§5.2）。
- `lastSavedHash: string|null` —— 上次落盘内容哈希；**打开即 seed 为加载后容器的 contentHash**（§5.2）；仅 seed 与成功写盘时更新。
- `lastNodeCount: number` —— 最近一次成功写的总节点数；用于区分"合法空"vs"异常空"（§5.1）。
- `dirty: boolean`（派生，不落地）—— 见 §2.2。

## 2. 现状盘点

| 关注点               | 当前位置                               | 问题                        |
| ----------------- | ---------------------------------- | ------------------------- |
| 1.5s 兜底定时器        | `Edit.vue:829-839`                 | 提前清零 `_isLoading`，半加载被当就绪 |

| 自动保存守卫            | `Edit.vue:543`                     | 仅 `autoSave` 一处，依赖易错布尔    |
| 覆盖写盘入口            | `Edit.vue:556+` `silentSaveToFile` | 直接覆盖，无备份/校验（经 shell.writeFile→主进程） |
| 异步初始化             | `Edit.vue:1528/1503/1510`          | 只管容器可见，不含 decode+构建+首帧加载态 |

### 2.1 同步重活（P1 才动）

`decodeSmm` + 构建实例 + 首帧布局是"打开大文件卡 15s"真凶。P0 不碰它，只保证"卡顿期间禁止保存"；P1 用 Web Worker 移出主线程。

### 2.2 `dirty` 的精确定义（硬伤B / 遗留3）

- `dirty = (contentHash(current) !== lastSavedHash)`。
- **`lastSavedHash` 的两处写入**：① **打开读取成功后 seed = contentHash(加载后容器)**（§5.2，与 seed 三者同块）；② `safeWriteFile` 成功回读后更新。除此之外不写 → 打开未编辑时 `dirty=false`，退出不触发写。
- 任意编辑操作只改内存，不在编辑时置 dirty；决策点才比对哈希，与"有修改才备份"原则一致。

### 2.3 `contentHash` 稳定性约束 + volatile 清单（遗留3 + 边界2）

- 输入 = **规范化后的容器数据**：JSON key 排序；排除 volatile 字段。
- **volatile（排除，不计入 dirty）白名单**：缩放/滚动/选中状态、**激活 sheet 索引**、**折叠/展开态**、`_mindlink` 等元数据、时间戳、版本元数据。
- **content（计入 dirty）黑名单**：节点文本/结构、**节点 x,y 位置**、样式、链接引用。
- 三个争议点拍板：**折叠=volatile**（折叠大分支不误判为"修改"）、**位置=content**（拖动重排算修改）、**激活 sheet=volatile**（切 sheet 不误 dirty）。
- 单测覆盖："同一内容、不同序列化顺序 → 同一哈希"；"仅 UI 缩放/仅折叠变化 → 同哈希（不误 dirty）"；"节点位置变化 → 哈希变化（判 dirty）"。
- 跨版本格式变化导致哈希对不上时，以"打开即重新 seed"自然校准，不会永久 dirty。

### 2.4 保存目标判定（遗留2：多工作簿竞态）

- **保存作用于"发起保存时显式捕获的 workbook id"**，而非瞬态 `activeWorkbook`。
- 切换序列（`Index.vue`）：`before-workbook-switch` → `apiSwitchWorkbook` → `workbook-switched`。在 `before-workbook-switch` 时 active 仍为旧 workbook，此时 `manualSave` 明确针对**旧 workbook id** 捕获并写；闸门读**该 id** 的 `loadPhase`，不受切换中途 active 翻到新簿影响。
- `silentSaveToFile` 接收显式 `workbookId` 参数，闸门按该 id 查 `loadPhase`/`lastGoodSize`。

## 3. 模块拆分原则（避免全押 Edit.vue，且理顺 Electron 写路径）

- `web/src/utils/saveGuard.js`（纯函数）：`shouldWrite({loadPhase, dirty, container, lastGoodSize, lastNodeCount, lastNodeCountTotal}) → {allow, action, reason}`，`action ∈ {'write'|'recover'|'deny'}`。
- `web/src/utils/writeSafety.js`（纯函数）：`evaluateDataIntegrity(container) → {totalNodeCount, ok}`。
- **写服务只在主进程**：`electron-app` 的 `safeWriteFile({mode, filePath, data, meta})`，经 IPC 接收渲染侧请求；`mode='recover'` 只写 `.recover`、`mode='normal'` 走备份+原子+回读。**渲染进程（开了 contextIsolation/sandbox）无直写任意路径的能力，绝不直写文件**（硬伤3）。  
  纯逻辑脱离 1500 行组件单测。

## 4. 状态机（P0a 落地基础态 + P1 补全 loading）

### 4.1 状态定义（硬伤1：P0 必须含 failed）

- `idle`：初始 / 未加载。
- `loaded`：**只由真实完成事件触发**（§4.4 真实事件）——`node_tree_render_end` + 根非空；**新建空白簿直接置 `loaded`**（可信空态，不等 render_end）；已存在近空 .smm 有根节点 → render_end 后 loaded。
- `failed`：**终态，P0 即落地**（不可推迟）。触发条件：decode 抛错 / 解析异常 / 加载后**无根节点**。配**明确错误态 UI**（非 loading 假转圈），保存按钮禁用并提示"加载失败，请关闭重开或恢复"。
- `loading`：**P1 补**。涵盖 decode + 构建 + 首帧期间，供进度条与 stall 探测器使用。

### 4.2 看门狗 = stall 探测器（P1，自适应，只报"慢"）

- **1.5s 定时器已在 P0a 删除**。
- 自适应阈值 `stallMs = max(15000, k×fileSizeMB, 3×历史加载时间滚动中位数)`：
  - **`k` 默认 `1500ms/MB`**（边界4）。
  - **"历史" = 按文件大小分桶的滚动中位数，持久化于 `<userData>/loadStats.json`**（非按路径、抗重命名）（边界4）。
  - **首开某文件无历史** → 中位数项退化为 0 → `stallMs = max(15000, k×size)`。
- 监听进度事件；超 `stallMs` 仍无进度且 `loading` → UI 标"加载较慢"，**不翻 `failed`**。`failed` 只来自 §4.1 真实错误，彻底消除 loading→failed→loaded 横跳。

### 4.3 异步化（让进度条真能渲染，P1）

- P1 把 `decodeSmm` + 容器解析移入 **Web Worker**（渲染侧 postMessage 原始字节，Worker 回传归一化 container）；构建实例与首帧在主线程分批 `await` 让出。
- 只有重活离主线程，`loading` 态进度条才真实可渲染。

### 4.4 验收

- 注入"渲染结束事件丢失"：断言 `loadPhase` 停在 `loading`（标"慢"），绝不误入 `failed`，期间不产生写盘。
- 注入坏 .smm：断言 `failed` + 错误态 UI + 保存禁用。
- **新建空白簿**：断言直接 `loaded`、可保存、不卡 idle。
- 大文件加载：断言 `loading` 期间主线程仍可响应。

## 5. 保存前校验 + `.recover`（P2）

### 5.1 闸门（纯函数 `saveGuard.js` + `writeSafety.js`）

- **闸门 A — 加载态**（P0a 已落地）：`loadPhase !== 'loaded'` → `action='deny'`。
- **闸门 B — 数据完整性（硬阻塞，含合法空判定，硬伤C + 边界1）**：
  - 取 `totalNodeCount = 跨所有 sheet 求和的总节点数`（**边界1：非"任一 sheet==0"**）。
  - 若 `totalNodeCount === 0`：
    - **且**该 workbook `lastNodeCount>0` 或 `lastGoodSize>0`（曾有过非空内容）→ `action='recover'`（写 `.recover`，不碰原文件）。
    - **否则**（纯新建、从未有内容的空簿，`lastNodeCount===0 && lastGoodSize===null`）→ 允许正常写（合法空状态）。
  - 缺 `sheets`/`root` 结构损坏 → `action='recover'`。
- **闸门 C — 体积比对（默认关闭软提示，v2 已降级）**：取 `lastGoodSize`；仅当用户显式开启"体积异常提醒"才作**非阻塞 toast**，不拦写；阈值可配、标注"不可靠启发式"。

### 5.2 `lastGoodSize` / `lastSavedHash` / `lastNodeCount` 生命周期（硬伤B + 硬伤2）

- **Seed 时机与顺序（硬伤2 关键）**：`openMindMap` / `openContainerAsNewWorkbook` 读取源文件成功后，**在同一同步块内先 seed 三者、再置 `loaded`**：
  1. `lastGoodSize = 文件真实字节数`
  2. `lastSavedHash = contentHash(加载后容器)`（保证"打开未编辑→退出"不触发写）
  3. `lastNodeCount = 加载后总节点数`（用于 §5.1 合法空判定）
  4. **校验根非空** → 置 `loadPhase='loaded'`；根空/异常 → 置 `failed`。
- **`node_tree_render_end` 处理器内部**同样遵循"先 seed 后置 loaded"顺序；seed 失败或根空 → `failed`，保证 autoSave 在 `loaded` 前无抢跑窗口（硬伤2）。
- **索引键**：按 **workbook id**（非路径），抗重命名/移动，多簿不串。
- **更新**：仅 `safeWriteFile` 成功回读后更新三者（§6.1 步骤4）。
- **新/未保存工作簿**：三者均 `null/0` → 闸门 C 跳过、闸门 B 走"合法空"分支。

### 5.3 `.recover` 生命周期（v2 已定义）

- 命名 `<原名>.recover.<YYYYMMDD_HHMMSS>.smm`，永不覆盖；每源保留最近 5，FIFO 裁剪。
- 隔离出文件关联双击与"打开最近"；收进应用内"恢复"面板；设置可"清空恢复文件"。

### 5.4 通道边界（硬伤3 重写：渲染绝不直写，全走主进程）

- **渲染进程无直写任意路径能力**（contextIsolation/sandbox 下必须经 IPC），v3"渲染侧直接写 .recover"在 Electron 架构下无法落地。
- 所有落盘统一经主进程 **`safeWriteFile({mode, ...})`**：
  - **`mode='recover'`**：只写 `<原名>.recover.<ts>.smm`，**不备份、不碰原文件、不产生 `.bak`**；渲染侧把 `{mode:'recover', data}` 经 IPC 交给主进程写。
  - **`mode='normal'`**：走 §6 的备份 + 原子替换 + 解析回读（其内部才生成 `.bak`）。
- 二者互斥，杜绝一次异常保存同时产 `.recover` 与 `.bak`（硬伤E）。

### 5.5 验收

- `writeSafety.test.mjs`：总节点数 0 / 空 sheets → 按 §5.1 条件命中 `recover` 或 `write`；多 sheet 单空 sheet（其余非空）→ 总数>0 → 不 recover。
- `saveGuard.test.mjs`：未 loaded → `deny`；体积闸开关行为；`recover` 不产生 `.bak`。
- 集成：注入零节点（曾有内容）container，断言原文件不变、生成 `.recover`、无 `.bak`。

## 6. 模块三：原子写 + 备份（覆盖前先备份、可回滚，P0b 落地）

**目标**：任何覆盖写都是"备份 → 原子替换 → 解析回读校验"，旧文件永不瞬间消失。

落点：收敛裸写为单一主进程服务 `safeWriteFile`（`recover` 模式见 §5.4，不由此走覆盖路径）：

1. **写前备份**：覆盖前复制旧文件为 `<原名>.bak`（带时间戳，保留最近 N 份）。**复用 `backupManager.js` 的 `snapshotNow`**。
2. **原子替换**：写 `<原名>.tmp` → `fs.rename(tmp, 原名)`（Windows 先 `unlink` 再 `rename`/`replaceFile`）。tmp 阶段崩溃原文件完好。
3. **解析回读校验（硬伤D + 边界3）**：写后**轻量解析回读**——`JSON.parse` + magic(`app==='smm-multisheet'`) + 根存在 + **总节点数 === 写入前计数**。轻量、不重建 MindMap 实例（避开 15s decode），又挡得住"内容乱但长度对"。校验失败 → 用 `.bak` 回滚并报警。
4. **更新基准**：仅当 2/3 成功才更新 `lastGoodSize`/`lastSavedHash`/`lastNodeCount`（§5.2 闭环）。

### 验收

- 扩展 `backupManager.test.mjs`："原子写 + 崩溃回滚""备份可恢复""回读解析失败回滚"。
- 注入"写盘中途被杀"：断言原文件未截断、`.bak` 存在。

## 7. 模块四（P0b）+ 模块五（P0.5）：退出异步化 + 强杀感知

### 7.1 退出异步化（P0b，可商榷9）

- `win.on('close')` / `beforeunload`：若有 `dirty && loadPhase==='loaded'`，`e.preventDefault()`，`await safeWriteFile` 完成再退。
- **`isQuitting` 标志位防死循环**：
  ```js
  let isQuitting = false
  win.on('close', (e) => {
    if (isQuitting) return
    if (hasDirtyAndLoaded()) {
      e.preventDefault()
      safeWriteFile(...).then(() => { isQuitting = true; win.close() })
    } else { isQuitting = true; win.close() }
  })
  app.on('before-quit', (e) => { if (!isQuitting) { e.preventDefault(); /* 走上面 close 流程 */ } })
  ```

### 7.2 强杀感知与恢复（P0.5，遗留1：澄清 + 补）

- **澄清**：P0 真实闸门 A 下，加载期间任何保存被拒 → 强杀时磁盘原文件**从未被写**，**不会文件损坏**；用户损失的只是未保存的内存编辑（任何应用强杀皆然）。因此 P0 三件套已堵住"文件损坏"路径。
- **补（P0.5）**：启动检测 `<userData>/.running.lock` 残留 → **先查主文件完整性**（可解析、非零）：
  - 主文件完好 → 仅删 lock、继续、**不弹恢复**（没丢数据）。
  - 主文件缺失/损坏/零字节 → 弹"上次未正常退出，是否恢复？"，按 `.recover > 最近 .bak > backupManager 快照` 推荐；**绝不用旧 `.bak` 覆盖完好原文件**。
  - 此外，即便主文件完好，也可在"恢复"面板提供"从自动快照恢复未保存草稿"的可选项（不强制、不覆盖）。
- P0.5 让"用户强杀后下次能感知并可选恢复草稿"，覆盖 P0 阶段强杀概率最高的场景。

### 7.3 验收

- 残留 lock + 主文件完好 → 启动不弹恢复、删 lock。
- 残留 lock + 主文件损坏 → 弹恢复、`restoreSnapshot` 调起。
- `before-quit` 单测：有脏数据 → 退出延后、写盘成功才退；写盘失败 → 回滚不丢原文件。

## 8. 实施分期（P0a / P0b 拆包，每包可独立出包、各带回归测试）

### 8.1 P0a — 状态机止血（纯前端，不碰主进程写服务）

| 内容                                                                                                           | 关闭的风险              | 改动面                       |
| ------------------------------------------------------------------------------------------------------------ | ------------------ | ------------------------- |
| **① 删除 1.5s 定时器**；`loadPhase` 增 `idle/loaded`/`failed`，**`loaded` 只由 `node_tree_render_end`+根非空触发，新建空白簿直接置 `loaded`**（硬伤1） | 定时器误标就绪导致半加载被保存；坏/空文件静默失败 | workbookState.js、Edit.vue、open 路径 |

### 8.2 P0b — 写安全（动主进程，独立于 P0a）

- **④ 覆盖前先备份（原子写全量）**：`safeWriteFile`（备份+tmp/rename+**轻量解析回读**+更新基准，硬伤D/边界3）。

### 8.3 P0.5 — 强杀感知（遗留1）

### 8.4 P1 — 状态机补全 `loading` + 异步化（修根本，§4）

- `loadPhase` 补 `loading`；stall 探测器（自适应、只报慢不翻 failed，`k=1500ms/MB`、历史持久化）；decode/parse 移入 Web Worker；进度条真实可渲染。

## 10. v4 修订小结（相对 v3）

1. **硬伤1（最关键）**：P0 必须自带 `failed` 终态（decode 错误/无根 → failed + 明确错误 UI），且新建空白簿直接置 `loaded`（可信空态不等 render_end），已存在近空 .smm 有根 → render_end 后 loaded。坏文件/空文件不再静默失败、新建空簿不再卡 idle。
2. **硬伤2**：强制"seed 三者先于置 loaded、同一同步块内完成"；render_end 处理器内部顺序 seed→校验根→loaded，任一失败→failed。闸门 A 在 idle 期间 deny，loaded 只在 seed 后可达 → autoSave 抢跑窗口关闭。
3. **硬伤3**：Electron 渲染进程无直写文件权，v3"渲染侧直接写"自相矛盾。重写 §5.4——所有落盘走主进程 `safeWriteFile(mode)`，`mode='recover'` 只写 `.recover` 不碰原文件不产生 `.bak`，`mode='normal'` 才走覆盖备份。
4. **边界1**：gate B 改为按**总节点数 == 0**（跨 sheet 求和）判定，消除多 sheet 单空 sheet 误伤。
5. **边界2**：`contentHash` 给出明确 volatile/content 黑白名单并拍板折叠=volatile、位置=content、激活 sheet=volatile。
6. **边界3**：回读校验定深为 `JSON.parse`+magic+根存在+总节点数===写入前计数，轻量不重建实例。
7. **边界4**：stallMs 的 `k=1500ms/MB`、历史按文件大小分桶持久化于 `<userData>/loadStats.json`、首开退化公式给定。
8. **战略拆分**：P0 拆为 **P0a（状态机止血，纯前端）** + **P0b（写安全，动主进程）** + P0.5（强杀感知），恢复"最小改动先上"。
