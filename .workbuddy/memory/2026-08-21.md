# 2026-08-21

## 为思绪思维导图(mind-map)添加“多工作表(类Excel)”功能并打包为离线.exe

### 需求
用户下载的 simple-mind-map（思绪思维导图）web 项目，一个文件只能有一个思维导图，
要求改成像 Excel 那样可含多个独立 sheet，并边改边编译成 .exe。

### 实现要点（源码在 web/src）
- `web/src/api/index.js`：新增多工作表容器，存于 localStorage 键 `SIMPLE_MIND_MAP_SHEETS`，
  结构 `{ activeId, sheets: [{ id, name, data:{root,theme,layout,config,view} }] }`。
  `getData/storeData` 保持向后兼容（旧 `SIMPLE_MIND_MAP_DATA` 自动迁移为单个 sheet）。
  新增：`getSheetList/setActiveSheetId/getActiveSheetData/addSheet/removeSheet/renameSheet/
  getSheetsContainer/loadSheetsContainer/isSheetsFile`。
- 新组件 `web/src/pages/Edit/components/SheetTabs.vue`：底部 Excel 风格标签栏，
  支持切换/新建/双击或右键重命名/删除（仅剩一个时拒绝删除）。
- `Edit.vue`：集成 SheetTabs，实现 `switchSheet/addSheet/removeSheet/renameSheet`
  （切换前先 manualSave 保存当前 sheet，再载入目标 sheet 完整数据）、
  `exportSheets/importSheets`，并在 mounted 调 refreshSheets、beforeunload 时保存。
  通过 `window.__LOCAL_APP__` 关闭“网页版仅供试用”提示。
- `Export.vue`：smm/json 导出增加“导出全部工作表”勾选（默认勾选），勾选时 emit `exportSheets`。
- `Import.vue`：handleSmm 用 `isSheetsFile` 识别多工作表 .smm，整体导入。

### 构建
- `web` 已带 node_modules。构建：`cd web && npm run build`。
- Node 22 + webpack4 报 `digital envelope routines::unsupported`，需
  `export NODE_OPTIONS=--openssl-legacy-provider` 再构建。构建产物在 dist/，
  copy.js 会把 dist/index.html 复制到根 index.html。

### 打包为离线 .exe（重新生成 electron 25.7.0 二进制）
- 关键事实：原 `思绪思维导图-win32-x64/` 里的 `思绪思维导图.exe` 启动文件**丢失**，
  且目录不完整（缺 electron 核心，nativefier 把核心嵌进了自定义 exe）。所以必须重新生成 exe。
- 用官方 electron 25.7.0 完整发行包重建：
  `cd pkg_tools && npm i electron@25.7.0`（设
  `ELECTRON_MIRROR=https://registry.npmmirror.com/-/binary/electron/`）下载到
  `pkg_tools/node_modules/electron/dist/`（163MB 二进制）。
- 把完整发行包（electron.exe + 运行库 + `resources/default_app.asar`）整体复制到
  `思绪思维导图-win32-x64/`，再把我的 app 放入 `resources/app/`
  （main.js 用 Node 内置 http 服务器监听 `127.0.0.1:51888` 托管 dist 再 `loadURL`；
  preload.js 用 `contextBridge` 暴露 `window.__LOCAL_APP__=true` 屏蔽网页试用提示）。
- 把 `electron.exe` 重命名为 `思绪思维导图.exe`。
- 机制：electron 从 `resources/app/package.json` 的 main 加载我的 app；
  `default_app.asar` 仅在无自定义 app 时显示欢迎页，有 app 时自动委派。
- 坑：npm 包 `electron` 的 index.js 只是“返回二进制路径字符串”的 shim，不是 API；
  本沙箱里 `require('electron')` 无法解析为内置模块，无法做无头渲染测试——
  不要再用无头方式验证，直接交付给用户双击实测。
- localStorage 在 `http://127.0.0.1` 源下可靠持久化（与原在线体验一致）。

### 第一次双击 → 白屏（ReferenceError: SheetTabs is not defined）
- 用户实测：弹窗指向 `chunk-vendors.js:36 ReferenceError: SheetTabs is not defined`。
- 根因：`Edit.vue` 的 `components: { ... SheetTabs }` 已注册，但**漏写了**
  `import SheetTabs from './SheetTabs.vue'` → 局部变量 undefined，Vue 运行时挂掉。
  （web/src 多文件改的过程中漏了一行 import；以后改 .vue 顺序固定 import → components → data → mounted。）
- 修复：在 `import OutlineSidebar` 之前加 `import SheetTabs from './SheetTabs.vue'`，
  重新 `npm run build`，把 `dist/` 覆盖到 `思绪思维导图-win32-x64/resources/app/dist/`。
- 复检：bundle 必须出现 `SheetTabs`、`SIMPLE_MIND_MAP_SHEETS`、至少需保留一个工作表、导出全部工作表四个串。
- 教训：Vue 组件新增/改 import 后，重建前**必须**在源码侧 grep 模板引用的每个组件名确认有对应 import。

### 第三次用户反馈：Ctrl+S 不保存
- 现象：按 Ctrl+S 没有保存/没反应（被浏览器或 Electron 默认菜单“保存网页/另存为”抢走）。
- 根因（两层叠加）：
  1. `Edit.vue` 原本用 `this.mindMap.keyCommand.addShortcut('Control+s', ...)`，
     而 simple-mind-map 的 `KeyCommand.onKeydown` 默认 `checkFn=defaultEnableCheck`
     **只在焦点在 document.body 或编辑节点时才响应**，否则直接 return 且**不 preventDefault**
     → 组合键被浏览器/Electron 默认行为吞掉。
  2. `main.js` 没设自定义菜单，Electron 用**默认菜单**，“文件→保存”绑定 Ctrl+S，
     在页面之前拦截并弹“另存为”。
- 修复：
  1. `Edit.vue`：移除 `keyCommand.addShortcut('Control+s')`；新增全局
     `window.addEventListener('keydown', this.onGlobalKeydown)`，监听
     `(ctrl||meta)+s`，`e.preventDefault()` 后调 `manualSave()` 并
     `$message.success('已保存当前工作表')`；`beforeDestroy` 里 `removeEventListener`。
     `manualSave` 调 `storeData(this.mindMap.getData(true))`（合并回当前激活 sheet 并落 localStorage）。
  2. `main.js`：`Menu.setApplicationMenu(Menu.buildFromTemplate([视图(重载/DevTools/缩放/全屏), 帮助(关于)]))`
     ——**不含“保存”项**，让 Ctrl+S 不被 Electron 菜单拦截。
- 澄清：自动保存本就一直在后台（`bindSaveEvent` 监听 data_change/view_data_change 每次改动都 storeData），
  用户数据基本没丢；Ctrl+S 是“立即保存+提示”入口，之前被焦点检查/菜单拦掉。
- 构建注意：`copy.js` 把 `dist/index.html` 移到项目根并**删除 dist 里的**；根 index.html 是构建产物，
  hash 每次 build 可能变（ebd9d339→d835b931）。覆盖到 `resources/app/` 时**必须同步根 index.html**
  并删掉其带回的 51.la 两段 script（离线 DNS 挂起→白屏）。HTML 只引 app.js+chunk-vendors.js，动态 chunk 由 app.js 运行时加载。
- 那次 build 后台任务 M82o4q 用 `| tail` 管道莫名卡死 7 分钟且 node 进程消失、dist 被清空未产出；
  改用无 tail 的后台 build（BYUmV0）23 秒正常完成。教训：此项目后台 build 不要接 tail 管道。
